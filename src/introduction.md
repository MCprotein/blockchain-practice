# 시작하기 전에

이 책의 목표는 Rust 문법과 블록체인 용어를 많이 외우는 데 있지 않다. 코드를 읽고 트랜잭션이 어떤 상태를 바꾸는지 설명하고 작은 스마트 컨트랙트를 테스트하는 것이 목표다.

특정 프로그래밍 언어 경력은 전제하지 않는다. 명령어를 실행하고 짧은 코드를 수정해 보려는 독자라면 시작할 수 있다. 블록체인은 단일 운영자가 관리하는 서비스와 실행 조건이 다르므로 다음 차이부터 잡고 간다.

| 단일 운영자가 관리하는 서비스 | 퍼블릭 블록체인 |
|---|---|
| 서버 운영자가 DB를 수정할 수 있다 | 합의된 규칙을 통과한 트랜잭션만 상태를 바꾼다 |
| 요청을 재시도하거나 관리자 작업으로 복구하기 쉽다 | 확정된 기록을 되돌리기 어렵다 |
| 내부 데이터는 접근 제어로 숨긴다 | 온체인 데이터는 기본적으로 공개된다 |
| CPU·메모리 비용을 서버가 낸다 | 호출자가 실행 수수료를 낸다 |
| 배포 후 코드를 곧바로 교체할 수 있다 | 변경·업그레이드 방식까지 설계해야 한다 |

## 어디까지 배우나

핵심 경로는 다섯 단계다.

1. Rust의 소유권, `Result`, 구조체와 열거형을 익힌다.
2. 블록체인의 상태 전이와 합의를 이해하고 작은 체인을 실행한다.
3. Ethereum의 상태 전이와 Solidity 컨트랙트를 Foundry로 테스트한다.
4. 같은 문제를 Solana의 계정 모델과 Anchor로 다시 본다.
5. Besu 검증자 네 개를 연결하고 QBFT 합의와 장애 허용 한계를 확인한다.

Ethereum 컨트랙트가 목적이라면 1~3장을 먼저 훑고 4장, 6~10장에 집중해도 된다. Solana 프로그램이 목적이라면 Rust 기초와 블록체인 모델을 다루는 1~5장, 11~12장을 순서대로 읽는 편이 좋다. 프라이빗 Ethereum 노드를 직접 운영해 보고 싶다면 6장을 이해한 뒤 13장으로 가도 된다.

Alloy, 브리지, 프록시, MEV, 영지식 증명처럼 중요한 주제도 많다. 하지만 첫 스마트 컨트랙트를 만들기 전에는 모두 옆길이다. 이 책은 기초 실행 모델과 첫 다중 노드 배포에 집중하고 나머지는 부록의 다음 학습 순서로 넘긴다.

## 예제의 검증 범위

코드 블록의 의미는 태그로 구분한다.

- `rust`: `mdbook test`가 검사하는 독립 예제
- `rust,compile_fail`: 컴파일 실패를 보여 주는 예제
- `rust,ignore`: 외부 크레이트나 프로젝트 문맥이 필요한 읽기용 예제
- `solidity`, `bash`, `json`, `toml`, `yaml`: 해당 도구나 설정 파일에서 사용할 예제
- `text`: 출력, 구조, 개념도

`mdbook test`가 통과해도 Solidity나 Anchor 코드까지 실행됐다는 뜻은 아니다. `practice/mini-chain`은 Cargo로, `practice/besu-qbft`는 Docker Compose로 별도 검증한다.

## 권장 학습법

한 장을 읽은 뒤 설명을 다시 읽기보다 작은 변형을 해 보자. 소유권 예제의 인자 타입을 바꾸고 미니 체인의 블록 데이터를 조작하고 Vault 테스트에서 공격 순서를 바꿔 보는 식이다. AI가 만든 코드도 정답으로 간주하지 않는다. 컴파일과 테스트 결과를 확인하고 입력에 따라 어떤 상태가 바뀌는지 직접 설명해야 한다.
