# 4. 블록체인은 무엇을 보장하는가

블록체인은 “해킹할 수 없는 DB”가 아니다. 서로 완전히 신뢰하지 않는 참여자들이 하나의 상태 변경 순서에 합의하도록 만든 복제 상태 머신(replicated state machine)에 가깝다.

## 상태 전이로 보기

은행 이체를 단순화하면 현재 상태와 명령으로 다음 상태를 계산한다.

```text
현재 상태 S: alice=10, bob=0
트랜잭션 T: alice가 bob에게 4 전송
전이 함수 F(S, T)
다음 상태 S': alice=6, bob=4
```

모든 노드가 같은 시작 상태, 같은 트랜잭션 순서, 같은 전이 규칙을 사용하면 같은 결과에 도달한다. 스마트 컨트랙트는 이 전이 규칙의 일부다.

여기서 결정적 실행(deterministic execution)이 중요해진다. 노드마다 현재 시각, 랜덤 값, 외부 HTTP 응답이 다르면 결과가 갈라진다. 그래서 컨트랙트는 일반 서버처럼 임의의 외부 API를 직접 호출할 수 없다. 외부 정보가 필요하면 오라클 같은 별도 전달 구조를 사용한다.

## 해시, 암호화, 서명은 서로 다르다

세 용어를 섞으면 블록체인 설명이 금방 흐려진다.

| 도구 | 질문 | 대표 용도 |
|---|---|---|
| 해시(hash) | 데이터가 바뀌었나 | 블록·트랜잭션 식별, 무결성 확인 |
| 암호화(encryption) | 허가된 사람만 읽게 할 수 있나 | 비밀 데이터 보호 |
| 디지털 서명(signature) | 이 개인키 소유자가 승인했나 | 트랜잭션 발신자 인증 |

해시는 입력을 고정 길이 값으로 요약한다. 같은 입력에는 같은 결과가 나오지만 해시만 보고 원문을 복원하는 용도는 아니다. 아주 작은 입력 변화도 전혀 다른 결과를 만든다.

디지털 서명은 개인키로 만들고 공개키로 검증한다. 검증이 성공하면 “이 공개키에 대응하는 개인키가 해당 메시지에 서명했다”는 사실을 확인한다. 현실의 사람 이름이나 법적 권한까지 자동으로 증명하지는 않는다.

## 블록이 하는 일

블록은 합의된 트랜잭션 묶음과 이전 블록을 잇는 메타데이터를 담는다. 체인마다 구조는 다르지만 보통 다음 정보가 있다.

- 이전 블록을 가리키는 해시
- 트랜잭션 집합을 요약하는 루트
- 블록 번호나 슬롯
- 합의에 필요한 증명과 제안자 정보

## 합의가 필요한 이유

네트워크 지연 탓에 노드마다 서로 다른 후보 블록을 보기도 한다. 공격자는 여러 신원을 만들거나 과거 기록 변경을 시도한다. 합의 프로토콜은 어떤 제안을 정식 기록으로 인정할지 정한다.

Sybil 공격은 한 참여자가 여러 가짜 신원을 만들어 의사결정 영향력을 부풀리는 공격이다. 작업 증명(Proof of Work)은 계산 자원과 전력 비용을, 지분 증명(Proof of Stake)은 예치한 자산과 위반 시 처벌 가능성을 신원 수 대신 사용한다. “노드 수가 많으니 다수결”이라고 설명하면 이 경제적 가중치와 프로토콜 규칙을 놓친다.

합의를 이해할 때는 세 질문을 나눠 보자.

1. 누가 블록을 제안할 수 있는가?
2. 노드는 어떤 후보를 정식 체인으로 선택하는가?
3. 언제 되돌리기 어려운 최종 상태로 보는가?

Ethereum의 현재 합의는 지분 증명이다. 검증자가 ETH를 예치하고 블록 제안과 증명(attestation)에 참여한다. 증명은 검증자가 본 체인의 머리와 체크포인트에 표를 보내는 메시지다. 상충하는 표처럼 규칙을 어긴 행동에는 예치금을 직접 깎는 슬래싱(slashing)이 적용될 수 있다.

## 불변성과 최종성은 절대값이 아니다

“블록체인에 쓰면 절대 못 바꾼다”는 표현은 지나치게 강하다. 기록을 바꾸려면 이후 블록과 합의를 다시 뒤집어야 해서 비용이 커진다는 쪽이 정확하다. 프로토콜의 최종성 규칙, 검증자 분포, 네트워크 상태, 애플리케이션이 기다린 확인 수에 따라 신뢰 수준이 달라진다.

컨트랙트 상태도 무조건 영구 고정되는 것은 아니다. 컨트랙트가 수정 함수를 제공할 수 있고 업그레이드 프록시를 쓸 수도 있으며 거버넌스가 매개변수를 바꿀 수도 있다. 무엇이 불변인지 코드를 기준으로 확인해야 한다.

## 블록체인을 쓰지 않는 편이 나은 경우

운영 주체가 하나이고 DB 수정 권한도 그 주체가 가져도 된다면 일반 데이터베이스가 더 싸고 빠르다. 공개 검증, 공동 소유 상태, 중개자 없이 이전 가능한 자산, 한 주체가 임의로 바꾸기 어려운 규칙이 실제 요구사항일 때 블록체인의 비용을 감수할 이유가 생긴다.

미니 체인 실습에서는 해시 연결과 합의가 서로 다른 문제라는 점을 코드로 확인한다.
